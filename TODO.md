## Synthetic clips from real-world map data (Google Maps Platform)

Render simulated flights over real places instead of (or alongside) the procedural terrains in
`testbed/synth/terrain.py`, using the Google Maps Platform integration in Google AI Studio
(announced 9 Nov 2026: https://x.com/GoogleAIStudio/status/2119837788937896234; one-click setup,
apps generated by Gemini from a description; data: map tiles, places, weather, routing,
3D buildings, Street View). Background: "5 cool things people are building with Google's Gemini 4
Neon" (https://generativeai.pub/5-cool-things-people-are-building-with-googles-gemini-4-neon-a679ef33dfb4),
item 4: a 3D game through real Tokyo streets built on Google Maps data.

### What each Maps data source would give drongo

| Data | Use in drongo simulations |
|---|---|
| 3D buildings | Real city geometry instead of procedural blocks: true heights, occlusion, parallax |
| Map tiles (satellite) | Real ground imagery for the ground texture under the 3D objects |
| Routing | Realistic paths for moving vehicles on real roads (moving targets, currently missing) |
| Weather | Plausible sun / haze / wind settings per place and time (`Look`, `--wind`) |
| Places | Pick named sites as orbit points of interest |
| Street View | Low value for aerial views; skip |

### Plan

1. **Prototype in AI Studio**: ask Gemini for a browser app that loads 3D buildings + tiles for an
   area and renders the camera view for a given pose (lat, lon, altitude, gimbal yaw/pitch/roll) with
   the horizontal FOV of a drongo `CameraModel`. Check that a known landmark projects where
   `FrameGeometry.en_to_pixel` says it should.
2. **Render pipeline**: export that renderer, drive it headless (e.g. Playwright) with the per-frame
   poses from `testbed/synth/flights.py`, capture frames, encode and write SRT / embedded telemetry
   with the existing `testbed.synth.demo` code (`render_clip` with a pluggable frame renderer).
3. **Ground truth**: real terrain is not flat. Record ground elevation (and building heights) in the
   truth file; full checking depends on the DEM / surface ground model on the roadmap
   (docs/accuracy.md), which these clips would then test.
4. **Moving objects**: cars following routing results, with their true trajectories in the truth file.
5. **Open-data variant for the public repo**: the same idea with OpenStreetMap buildings and roads
   (Google's own Gemini 4 Neon demo, NEON SCRAMBLE, used a 3D map built from OpenStreetMap). OSM
   footprints + heights map directly onto `testbed/synth/scene.py` `Building` objects, and OSM is
   redistributable (ODbL, with attribution), so those clips can ship with drongo.

### Constraints

- AI Studio Maps use is free within a daily quota (resets every 24 h); production use needs a paid
  Google Cloud billing account.
- Check the Google Maps Platform terms before publishing clips rendered from Google data: caching,
  offline use and redistribution of map content are restricted, and attribution is required. Likely
  outcome: Google-based clips stay local, OSM-based clips go in the repo.
- Keep the Maps API key out of the repo (environment variable).
